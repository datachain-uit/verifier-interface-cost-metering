# Reproducibility package for on-chain zero-knowledge verifier cost comparisons across public-input counts and metering specifications

## 1. What this artifact reproduces

This repository is the reproducibility package of the accompanying article. The article compares the on-chain
verification cost of Groth16, PLONK and FFLONK verifiers as the number of verifier-visible public inputs *k* grows,
under three metering specifications: EVM gas (Osaka), EraVM computational gas (protocol 29, with protocol 27 as a
historical validation regime) and ZKsync OS v32 gas and native resource. It contains:

- the frozen protocols: the internal pre-registration C1, its FFLONK setup amendment, the separate prospective test C2,
  the post hoc re-trace protocol and the prover protocols D1, D2 and D3;
- the frozen evidence: the P0 feasibility study, the pilot, full and FFLONK measurement campaigns, the post hoc audits,
  and the prover data of D1, D2 and D3;
- the setup material that the evidence depends on: powers-of-tau file, circuits, keys, verifiers and proofs;
- the scripts that derive every reported value, table and figure from the frozen evidence (`analysis/`), and runners that
  re-execute the frozen scorers and analysis scripts (`scoring/`);
- the generated outputs used in the article: values, Tables 1–3, Supplementary Tables S1–S25 and Figs. 1–5.

Three levels of reproduction are supported:

| Level | Meaning | Entry point | Needs |
|---|---|---|---|
| **1. Integrity** | every object is present with its recorded SHA-256 or explicitly classified; every frozen manifest is accounted for | `./scripts/verify-artifact.sh` | Python 3 |
| **2. Deterministic regeneration** | (a) values, tables and figures regenerate byte for byte from the frozen evidence; (b) the frozen scorers and analysis scripts, re-run on the frozen evidence, reproduce their frozen outputs | `./scripts/regenerate-outputs.sh`, `python3 scoring/rescore.py --all` | Python 3.10 (reference 3.10.12), matplotlib 3.10.9 and the Liberation Sans 2.1.5 font files for figures (section 15) |
| **3. Experimental rerun** | new measurements with the pinned toolchain and local chains, new proofs, new prover timings | the protocol documents under `protocols/` | the pinned binaries, chains and hosts of section 14; days of machine time |

Levels 1 and 2 run in minutes on a laptop. Level 3 is a full experimental campaign; see section 14.

## 2. Title and scope

The scope is the cost of *verifying* a proof on chain, measured per verification transaction, for one circuit family
(a depth-11 Poseidon Merkle-membership credential relation, extended to *k* public inputs by context tags) and the pinned compilers, nodes and chains listed in
`provenance/EXTERNAL-PINS.tsv`. Prover timings (D1–D3) are supporting evidence about proof generation on two named
hosts; they are descriptive and host-specific. Nothing here is a security evaluation: the powers-of-tau files used for
the setups were generated by the authors for measurement purposes (single contribution) and are not trusted setups.

## 4. Quick integrity check (Level 1)

```
./scripts/verify-artifact.sh
```

Each object of `provenance/OBJECT-CLASS.tsv` is reported as `PRESENT HASH-MATCH`, `WITHHELD`, `REGENERABLE`,
`EXTERNAL-PIN` or `GIT-LFS-PENDING`; anything else, including a missing or unexpected file, is an `ERROR` and the script
exits non-zero. Every entry of every frozen package manifest must be present with its frozen hash or be a classified
object with that same hash. The script uses only the Python standard library.

## 5. Values

```
python3 analysis/derive_values.py --deep --check
```

`analysis/derive_values.py` reads only the frozen packages (every manifest and every file it reads is hash-checked;
`--deep` re-hashes every file of every package) and writes `generated/article-values.tex` (one `\vval{key}` macro per
reported value), `generated/article-values.tsv` (key, LaTeX value, raw value, unit and frozen source of each value),
the data files in `generated/data/` and `generated/MANIFEST.json`. It never refits, re-scores or changes a tolerance;
recorded outcomes of the registered tests are cross-checked against the frozen scorer outputs. `--check` regenerates
in memory and requires byte identity with the committed files.

## 6. Tables 1–3

```
python3 analysis/tables/src/make_tables.py --check
```

Tables 1–3 are rendered from `generated/data/` only (`tables/T1-regimes.tex`, `T2-structure.tex`, `T3-tests.tex`;
input and output hashes in `tables/TABLES-MANIFEST.json`).

## 7. Figures

```
python3 analysis/figures/src/build_figures.py --check
```

Figs. 2–5 are plotted from `generated/data/` only (plotting code computes no scientific quantity) and written as vector
PDF and SVG; each PDF must embed all fonts, contain no Type 3 font and no raster image. Byte identity of the PDFs requires
matplotlib 3.10.9 and the Liberation Sans 2.1.5 font files whose hashes `figures/FIGURES-MANIFEST.json` records (for Ubuntu
24.04 see `environment/README.md`).

Fig. 1 is a conceptual diagram without data. It was drawn in draw.io and is not generated by a script: `figures/Fig1.drawio`
is the editable source, `Fig1.pdf` / `Fig1.svg` the export, and `figures/FIG1-EXPORT.json` records the tool, version,
commands and hashes. The build checks these hashes and applies the same vector gates.

## 8. Supplementary Tables S1–S25

```
python3 analysis/supplement/src/make_supplement_tables.py --check
```

Tables S1–S25 (`tables/supplement/`) render values that already exist in frozen protocol, scoring or evidence files or
in `generated/data/`, with display formatting only. Each input is hash-checked against its package manifest; Table S8
lists the digests of all frozen packages and Table S25 the D3 source files with their hashes (published under
`data/prover/d3/source/`).

All of sections 5–8 in one command:

```
./scripts/regenerate-outputs.sh            # check mode; --write regenerates in place
```

## 9. C1 scoring

The pre-registration `protocols/c1-preregistration/` fixed the model, parameter ledger, held-out matrix, numeric
predictions, tolerances, falsifiers and the scorer (`scoring/score_c1.py`) before any registered measurement. The
registered evidence is under `data/c1/{pilot,full,fflonk}/evidence/`; the scorer outputs are under
`data/c1/full/record/scoring/` and `data/c1/fflonk/record/scoring-c1/`, each with its recorded invocation.

```
python3 scoring/rescore.py c1-full c1-fflonk        # re-run the frozen scorer; outputs must be byte-identical
python3 scoring/rescore.py c1-predictions            # re-run the frozen prediction generator on the P0 data
```

Every output is compared byte for byte except `p0_model_check.csv` of `c1-predictions`: the frozen predictor emits the
same complete row multiset, but filesystem-dependent unsorted glob ordering can permute row order, so this one output is
compared as an order-insensitive multiset of complete rows (header exact, duplicates counted) and reported as
`IDENTICAL-AS-ROW-MULTISET` (`scoring/README.md`).

## 10. C2

C2 is a separate prospective test, frozen after the F4 outcome and outside C1 (`protocols/c2-forward-test/`): stage 1
fixed the model, calibration and scoring rule, stage 2 the structural derivation and predictions; the scores are in
`data/c1/fflonk/record/scoring-c2/`.

```
python3 scoring/rescore.py c2-calibration c2-internal-check c2-predict c2-score
```

## 11. Post hoc analyses

Post hoc and descriptive, not registered evidence: the source-level audit of the F4 residual
(`data/posthoc/native-cost-audit/`), the deterministic re-trace of heap-expansion events (protocol
`protocols/posthoc-heap-retrace/`, data `data/posthoc/heap-retrace/`), and the residual and native-per-gas tables of the
full campaign (`data/c1/full/record/post-registered/`).

```
python3 scoring/rescore.py posthoc-audit posthoc-retrace-count c1-residual c1-npg-per-proof c1-bridge
```

Re-tracing the proofs themselves (`data/posthoc/heap-retrace/scripts/retrace*.js`) needs the pinned EVM tooling and is
Level 3.

## 12. Prover analyses D1, D2, D3

Supporting, descriptive evidence on proof generation: D1 (pre-registered padding contrast, Host A), D2 (allocation and
backend timings, Host B) and D3 (descriptive re-analysis of Host A prover timings; its source files are published under
`data/prover/d3/source/`).

```
python3 scoring/rescore.py d1 d2 d3 d2-side-by-side
```

## 13. Raw evidence

Per-cell raw records (`records.jsonl` per attempt, traces, logs, compiled artifacts, harness copies and run manifests)
are inside the evidence packages, each listed in its package manifest. Frozen run logs contain machine-local execution
provenance (host names, user names, paths); they contain no credentials, and the only keys in them are the publicly
documented development accounts of local test chains.

## 14. Full-rerun requirements (Level 3)

A full rerun repeats the experiments, not the analysis. It needs:

- the pinned toolchain of `provenance/EXTERNAL-PINS.tsv` (circom 2.1.6, snarkjs 0.7.5, solc 0.8.20, zksolc 1.5.15 with
  era-solc 0.8.20-1.0.2, hardhat 2.29.1 with EDR 0.12.0-next.23, anvil-zksync 0.6.11, zksync-os-server v0.23.0 with
  the v32.0 local chain, foundry anvil 1.5.1), verified against the recorded SHA-256 values;
- the harnesses copied inside each evidence package (`harness/`) and the protocol of each campaign (pilot, full,
  negative controls and FFLONK cells in `protocols/c1-preregistration/` and `protocols/c1-amendment-fflonk-setup/`);
- for the prover analyses, the kits in `protocols/prover-d1/kit/`, `protocols/prover-d2/` and
  `protocols/prover-procedure/kit/`, the pinned base image, and comparable hosts. Host A was an Apple M5 machine running
  the Linux arm64 image; Host B an x86-64 Xeon workstation with CPU-set allocations. Timings depend on the host and are
  not expected to reproduce numerically elsewhere; the protocols state what is compared.

Gas and native-resource measurements are deterministic for a given toolchain and input, so a faithful Level-3 rerun of
the verifier-cost cells is expected to reproduce the recorded per-proof values; prover timings are not.

## 15. Environment and pins

`environment/README.md` describes the reference environment of Levels 1 and 2 (Python 3.10 with Python 3.10.12 as the
verified reference, matplotlib 3.10.9, numpy 2.2.6, the Liberation Sans 2.1.5 font files, poppler-utils for the figure
gates; node and npm only for key regeneration). Values, Tables 1–3, Tables S1–S25 and all scorer re-runs need only the
Python standard library; byte identity of the re-scoring outputs is verified with Python 3.10.12. Under Python 3.13 the
D1, D2 and D3 analyses differ only in the last digit of some `sd` / `cv` values, so Python 3.13 is not a reference
environment for exact reproduction. Every third-party
component is pinned in `provenance/EXTERNAL-PINS.tsv` with its version, recorded hash where one exists, and the
frozen file that records it.

## 16. Withheld, regenerable and large objects

`provenance/OBJECT-CLASS.tsv` assigns every object exactly one class:

| Class | Meaning |
|---|---|
| `GIT` | published in this repository |
| `REGENERABLE` | not stored; rebuilt deterministically and validated against its frozen hash. The 15 PLONK proving keys (`provenance/REGENERABLE.tsv`): `./scripts/regenerate-keys.sh --place` rebuilds them from the published R1CS files and `setup/ptau/pot16_final.ptau` with the pinned snarkjs 0.7.5 |
| `WITHHELD` | not published; listed with path, SHA-256 and size in `provenance/WITHHELD.tsv`. Eight non-scientific execution-environment records inside frozen packages; no derivation reads them. The frozen manifests still list them, so the verifier reports them as withheld rather than missing |
| `GIT-LFS` | exact large files that ordinary Git cannot hold and that this artifact does not regenerate, stored with Git LFS in this repository: the research powers-of-tau file of power 19, which cannot be regenerated, and the four FFLONK proving keys, whose independent regeneration is not established and not claimed. Size, SHA-256 and BLAKE2b-512 of each are in `provenance/LFS-OBJECTS.tsv`. Reported as `GIT-LFS-PENDING` while absent or a Git LFS pointer (whose oid and size must equal the recorded ones), and as `PRESENT HASH-MATCH` once the object itself is present with its recorded SHA-256 |
| `EXTERNAL-PIN` | third-party tools and sources, not redistributed; obtained upstream and checked against `provenance/EXTERNAL-PINS.tsv` |

The prover-procedure document cited by the D2 protocol is published as a verbatim extract
(`protocols/prover-procedure/PROVER-PROCEDURE-v3-EXTRACT.md`; source hash and line ranges in `provenance/EXTRACTS.tsv`).
Some immutable frozen records carry internal identifiers; `provenance/LABELS.md` explains them.

## 17. Limitations

- **FFLONK setup material.** The FFLONK verifiers, verification keys, proofs, logs and measurements are published. The
  research powers-of-tau file of power 19 used for the FFLONK setup and the four FFLONK proving keys are stored with Git
  LFS (class `GIT-LFS`; size, SHA-256 and BLAKE2b-512 in `provenance/LFS-OBJECTS.tsv`, consistent with the frozen records
  `setup/fflonk/ptau-local/PTAU-LOCAL-RECORD.json` and `setup/fflonk/records/FFLONK-ARTIFACTS-SHA256SUMS`). Without them,
  re-verifying the FFLONK keys against the powers of tau and re-proving with identical keys are not possible; every
  reported FFLONK result remains reproducible from the published verifiers and proofs. The powers-of-tau file cannot be
  regenerated (the entropy of its single contribution was discarded), and independent regeneration of the four proving
  keys from the circuit sources and the powers of tau is not established and is not claimed.
- **Withheld records.** Eight records are withheld (section 16); their hashes keep the frozen manifests verifiable.
- **Prover timings** are host-specific (section 14).
- **Setups are not trusted setups** (section 2).
- **Figure byte identity** depends on the matplotlib version and font files (section 7); SVG files are inspection copies,
  the PDFs are the masters.
- **Level 3** has not been repeated by a third party.
