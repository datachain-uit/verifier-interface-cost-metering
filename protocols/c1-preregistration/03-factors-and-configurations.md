## 2. Held constant

Merkle depth d = 11; BN254; synthetic corpus (`14-…`, 8 instances, j = 0…7); solc 0.8.20, EVM version Paris, optimizer
200 runs (V1 primary profile); zksolc 1.5.15 + era-solc 0.8.20-1.0.2, `-O3`, size fallback (V1 pins); generated managers
(root check on input[0] + verifier call + event, V1 semantics); one transaction per block; fees fixed by override
(ZKsync OS: native price 0xf4240, pubdata price 0, `general_ephemeral = true`); Groth16 phase 2 = one contribution + public
beacon; PLONK keys deterministic from the V1 power-16 ptau (sha256 `4a64b121…`).

## 5. Order

Within a run: deploy verifier → deploy manager → set issuer → add the 8 roots → `verifyCredential` j = 0…7 →
direct `verifyProof` j = 0…7 → controls (`17-…`). Cell order inside a campaign is the deterministic permutation
`sha256("V2-C1-order|" + campaign + "|" + cell_id)` ascending. Each (cell, regime level) runs on a fresh node instance
(EDR: fresh in-process network; anvil-zksync: fresh process; ZKsync OS: fresh L1 state + ephemeral server).
